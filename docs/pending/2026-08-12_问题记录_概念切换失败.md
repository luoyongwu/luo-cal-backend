# 问题记录：用户显式切换概念指令未生效

**日期**：2026-08-12
**测试对象**：用户5，概念1.1（极限简介）
**状态**：现象已复现三次，根因待排查，尚未修复

---

## 现象概述

概念1.1完成12轮问答后，用户尝试切换到"可分离变量微分方程"新主题。连续三次不同强度的切换请求，系统均未真正执行切换。

## 复现步骤与观察结果

**第1次尝试**（普通请求切换）
用户表达希望练习"可分离变量微分方程"。
系统回应：承认这是个好主题，但要求先完成当前极限题，随后直接生成一道新的1.1类型极限题（同函数 f(x)=(x²-4)/(x-2)，求lim(x→2)f(x)）。
→ 用户的切换请求未被作为待处理条件记录，直接被新题目覆盖。

**第2次尝试**（强指令："立即切换，不需要确认，不需要过渡性问题，直接开始微分方程教学"）
系统回应：未直接执行，而是抛回选择问句——"你想继续完成这道极限题，还是放弃它，转到可分离变量微分方程？请告诉我你的选择，我会立刻按你说的做。"
→ "不需要确认"这一元指令未被解析执行，被当作普通对话内容处理。

**第3次尝试**（用户明确选择："转到可分离变量微分方程，不再继续极限题"）
系统回应：未切换，而是重新生成了与第1次几乎完全相同的1.1题目（同一函数、同一引导问题："请先思考：当x=2时，直接将x=2代入函数f(x)，会发生什么？你能计算出f(2)的值吗？"）。
→ 用户的明确选择被忽略，系统状态似乎回退/重置到了之前的1.1出题逻辑。

## 伴随观察：Leakage Score 显示异常

上述三轮交互期间，前端 "Leakage Score" 显示始终固定为 **0/3**，未见变化。需确认这是否为此前已修复的"stale display"问题（Session 3测试中记录过：因未清空 `leakage_log` session state 导致前端显示滞后）的**回归**，还是本次场景下合理的、未触发leakage检测的正常表现。

## 疑似根因方向（待验证，非结论）

1. 用户的显式控制类指令（切换主题、跳过确认）可能没有专门的解析/执行通道，被当作普通对话文本喂给生成模型，模型仍按默认教学策略（先出同类题/先确认）处理。
2. 可能与 Concept Scope 状态机的释放条件有关——"用户显式换题"未被纳入可强制触发 closed 状态的信号列表，只有内部教学逻辑判定的"已充分掌握"才会释放。
3. Leakage Score 显示可能存在与切换失败共享的 session state 管理缺陷，也可能是独立的、之前已修复问题的回归，需分别排查。

## 后续建议

- 该问题独立于A2（OLE并行标签检测）的观测窗口，可以并行排查，不需要等A2验证完成。
- 建议先确认 Leakage Score 的显示逻辑是否读取了正确的最新状态（回归 vs. 正常），这个相对容易独立验证。
- 切换失败的根因排查建议先确认"用户指令"在当前 pipeline 中是否有被单独解析的环节，还是全部混在对话历史里交给模型自由决策。
