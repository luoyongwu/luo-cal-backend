# Luo-cal — Design Notes（架构决策日记 / ADR）

**性质：** 本文档不记代码 Bug，不记功能上线——那些记在 `THEORY_CHANGELOG.md`（理论变更）和 `constraints_changelog.md`（约束变更）里。这里只记**"当时为什么做出这个选择"**。几年后新人加入或者项目开源，翻开这本日记，应该能瞬间看清架构师当时的心路历程——包括权衡过什么、放弃了什么、为什么。

**格式：** 每条记录含背景（Context）、决策（Decision）、后果（Consequences）三段。决策一旦记录，除非被后续 ADR 显式取代，否则视为当前有效。

---

## ADR-001：先冻结接口，再写具体算法

**日期：** 2026-07-05
**状态：** Accepted

**背景（Context）：** Phase 2 要建的 Evidence Aggregation Engine，相当于给整个认知诊断系统装一颗"芯片"。传统开发直觉是立刻去写芯片里的具体数学公式（贝叶斯更新方程），但这样做的代价是：一旦未来要换算法（隐马尔可夫、Transformer Memory、甚至端到端大模型），整条从数据库到前端的管道都可能被迫跟着重构。

**决策（Decision）：** 不管里面装的是贝叶斯、HMM 还是未来的大模型，先把"插槽"的形状定死——`EvidenceAggregator` 和 `CognitiveInertiaDamper` 两个接口在 Phase 2 编码开始前先冻结，写进 PCSA 文档，作为后续所有实现的验收标准。

**后果（Consequences）：** Phase 2 的实际编码工作量不会因此减少，但换算法、跨学科扩展（v4.0）时前端和数据库不需要承受重构摩擦力。代价是前期多花时间设计接口而非直接看到进度——这是刻意的取舍，用今天的设计时间换未来的重构成本。

## ADR-002：State Transition Policy 的四大不变量，认识论优先于工程便利

**日期：** 2026-07-05
**状态：** Accepted

**背景（Context）：** State Transition Policy 最初只写了三条简单约束（Stage 可逆、Evidence 可追溯、Identity 不固定），偏工程清单，没有说清楚"为什么"。

**决策（Decision）：** 升级为四条不变量，每条都赋予认识论意义，不只是技术规则：
1. **可逆性**——保护学生的自我修正主权，系统不能是"一考定终身"的黑箱评级机器
2. **可追溯性**——系统对学生的每个论断都必须能拉出真实证据"小票"，拒绝黑箱断言
3. **不可绕过核心推断链路**——禁止用错题数量直接映射最终状态这类"抄近路"，重申命题1的多对多映射
4. **推断性非事实性**——Dashboard 展示的是"当前最合理推测"（Posterior），不是死结论（Reality）

**后果（Consequences）：** 这四条不变量成为 Phase 4 Constitution Audit 的直接依据，也是未来任何人提议"为了效率牺牲某条不变量"时的挡箭牌——性能优化、简化实现都不能突破这四条线。

## ADR-003：认知惯性阻尼从聚合引擎中剥离为独立组件

**日期：** 2026-07-05
**状态：** Accepted

**背景（Context）：** 最初的设计把"升级门槛从严（N≥5）"和"时间衰减"这两个阻尼逻辑，直接写在贝叶斯计算的描述里，和概率数学混在一起。这意味着未来换算法（比如换成 HMM）时，教学策略逻辑要跟着重写一遍——即使教学策略本身完全没有变化。

**决策（Decision）：** 拆成两个独立组件，职责单向：
- `EvidenceAggregator`：只管根据历史客观算出"纯净"概率，不掺杂任何教学判断
- `CognitiveInertiaDamper`：接收纯净概率，结合升级门槛、时间衰减等教学策略，决定这个概率能不能真的转化成状态变化

数学概率计算与教学业务策略彻底剥离，换其中一个不影响另一个。

**后果（Consequences）：** Phase 2 的工作量拆成两块（原 5-7 天的 Aggregation Engine 拆成约 4-6 天 Engine + 1-2 天 Damper），总时间相近，但未来算法迭代（比如把贝叶斯换成 Transformer Memory）时，阻尼策略代码完全不用动，反之亦然。

## ADR-004：N≥5 收敛阈值降级为工程超参数，脱离 Volume I 理论承诺

**日期：** 2026-07-05
**状态：** Accepted

**背景（Context）：** N≥5 这个具体数字最初写在 Ontology §4 v2.0 设计里，容易被误解为"宪法级"的理论承诺——如果未来实验证明 N=7 更合适，修改它似乎需要走 Constitution 修订流程（理论论证 + 实证验证），门槛过高。

**决策（Decision）：** 明确 N≥5 只是**可验证、可调的工程超参数**，记录在 Implementation 层（PCSA 文档 / 未来的算法说明文档），不写入 Volume I 宪法。理论层的承诺是"存在阻尼机制，防止状态剧烈震荡"；N 的具体取值是这个承诺的一种当前实现，可以像调收音机音量一样随时通过 A/B 测试调整，只需要工程验证，不需要理论论证。

**后果（Consequences）：** 未来调整 N 值（或替换成更复杂的动态阈值函数）只是 Implementation 层的变更，记录在 `constraints_changelog.md` 即可，不需要走理论宪法修订流程。这条决策本身反而更清晰地划出了 Constitution 和 Implementation 的边界：理论层承诺"机制存在"，不承诺"参数取值"。

## ADR-005：Evidence Aggregator 的两处修正——置信度公式的数学漏洞，与最大无知原则的一致执行

**日期：** 2026-07-05
**状态：** Accepted

**背景（Context）：** `BAYESIAN_AGGREGATOR_SPEC_v0.2.md` 的候选设计经过三方审阅（Claude 起草 → DeepSeek 补充数学增强 → Gemini/DeepSeek 二次确认）后，收敛出两处需要拍板的分歧。

**决策 1——置信度公式：两个因子相乘，不能只用熵。**

三方review中曾提议用纯熵公式 `confidence = 1 − H/H_max` 替代原先"只看证据数量"的公式，理由是原公式无法区分"十条一致的证据"和"十条矛盾的证据"。但这个替代方案本身有一个更隐蔽的漏洞：**只要有一条证据、且 100% 指向单一世界，熵为 0，算出来的置信度就已经是 1.0**——用一次观察就宣称绝对确定，这在认识论上比原来的问题更严重。

最终方案：`evidence_factor`（证据量是否足够）和 `concentration_factor`（证据方向是否一致）两个独立因子相乘，缺一不可。只有"足够多 + 足够一致"的证据才能让置信度真正逼近 1。

**决策 2——最大无知原则要一致执行，不能挑着用。**

`ABSOLUTE_VALUE` 的机制归因最初提议 0.3/0.7（凭直觉），后来改为 0.5/0.5，理由是"Ontology 没给定量依据，拍脑袋的数字答不上审稿人的问题"。但同一轮讨论里，`StructuralReasoning` 的信号级分割（`IVT_MVT_CONFUSION→{FWM:0.7,AWM:0.3}`、`WASHER_TRAP→{FWM:0.2,AWM:0.8}`）却基于"错误语义更贴近哪个 World"的直觉被保留了下来——同样没有 Ontology 原文的定量依据，却被视为"更准确"而不是"不诚实"。

这是一个未被察觉的双重标准：如果拍脑袋的比例在一处是问题，在另一处却是优点，这个区分经不起审稿人的追问（"旋转体积分的空间直觉占 80% 的证据在哪里？"）。

**决策：** 一致执行最大无知原则。所有未经 Ontology 原文定量支持、也没有真实 telemetry 数据支撑的分割点，一律 0.5/0.5，没有例外。`signal_overrides` 这张表在架构上保留（为未来 telemetry 反推真实比例留接口），但当前所有条目的数值都等于均匀分布——即当前版本里这张表是占位声明，不影响计算结果。

**后果（Consequences）：** 论文里可以完全统一地陈述："v1.0 基线阶段，所有 Ontology 原文未给出量化比例的交叉映射点，一律采用最大无知原则赋予均等先验；所有参数的精确取值由后续 Telemetry 长期数据反向校准。"没有需要分别解释的例外情况，审稿人问不出"这个数字哪来的"这种无法回答的问题。这比任何一个更"准确"但说不清来源的直觉数字都更经得起时间检验。
